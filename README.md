### Задание 1: API Gateway

Задача 1: API Gateway
Предложите решение для обеспечения реализации API Gateway. Составьте сравнительную таблицу возможностей различных программных решений. На основе таблицы сделайте выбор решения.

Решение должно соответствовать следующим требованиям:

- маршрутизация запросов к нужному сервису на основе конфигурации,
- возможность проверки аутентификационной информации в запросах,
- обеспечение терминации HTTPS.

Обоснуйте свой выбор.

### Решение 1

Будем вести сравнение между тремя решениями с открытым исходным кодом: Kong API Gateway, Apache APISIX, Nginx.

Сравнителльная таблица:
https://docs.google.com/spreadsheets/d/1YaF9uXmv2qfWO1LoqxRk6Jehunn5VyV69kBBFbztWbA/edit?usp=sharing

На мой взгляд, лучшим выбором является Apache - хоть под критерии подходит и Kong, но он имеет бОльшую сложность управления и настройки, имеет необходимость отдельно управлять БД в классическом режиме (PostgeSQL), а также не все плагины аутентификации доступны не в enterpise-версии. Также он бы больше подошел для интеграции с Kubernetes. На этом фоне для более простого проекта оптимально подошел бы Apache.

В любом случае, эти 2 решения в любом случае лучше подходят, чем Nginx, где изменение маршрутов или добавление нового сервиса требует перезагрузки, нет необходимости вручную править конфигурационные файлы веб-сервера и т.д.


### Задание 2: Брокер сообщений

Составьте таблицу возможностей различных брокеров сообщений. На основе таблицы сделайте обоснованный выбор решения.

Решение должно соответствовать следующим требованиям:

- поддержка кластеризации для обеспечения надёжности,

- высокая скорость работы,

### Решение 2

Будем сравнивать RabbitMQ, Apache Kafka и NATS JetStream.

Сравнительная таблица:
https://docs.google.com/spreadsheets/d/1YaF9uXmv2qfWO1LoqxRk6Jehunn5VyV69kBBFbztWbA/edit?gid=213227401#gid=213227401

Более подходящим является RabbitMQ - наибольшая простота эксплуатации (в отличие от Kafka со сложным администрированием), интуитивно понятный веб-интерфейс, достаточно высокая скорость работы, надежность (Использование механизма Quorum Queues). Если же приоритетом является big data и максимально высокая пропускная способность, выбор пал бы на Kafka.
